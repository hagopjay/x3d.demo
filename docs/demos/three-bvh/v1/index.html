What stays the same

The X3D. The scene is a plain ElevationGrid, a TouchSensor, a Transform and one ROUTE from hitPoint_changed to set_translation. Nothing in it knows about a tree.

The answer. The race button also checks that the tree and the plain raycast hit the same point on the same ray; a ray counts as the same when the two points are within a millionth of a unit.

Where the time goes

Once: building the tree on the first pick (shown under step 1). Per ray: a walk down a few dozen boxes instead of a loop over every triangle. The bridge only builds a tree for a mesh of 2,000 or more triangles and leaves skinned (HAnim) geometry alone, because it changes every frame.

Not changed: drawing. The GPU still draws every triangle; the tree speeds up questions asked on the CPU: picking, sensors, scans.

How it plugs in

Put the library on the page and the bridge notices:

import * as MB from 'three-mesh-bvh';
window.MeshBVHLib = MB;
// body.bvhOn = false  -> plain raycast
// body.pickStats      -> calls, ms, trees
Timings on this page are measured live in your browser on your machine; nothing is pre-recorded. The scan's "plain" time is an extrapolation from a few plain rays and says so when shown. Libraries: three r187, three-mesh-bvh 0.9.18, both from jsDelivr.
