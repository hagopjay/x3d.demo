Demo 82 · Fault Court v1 · 26 Nov 2026 · pre-registered

Three formats, one set of mistakes, each judged by its own court

One small scene was written natively in X3D 4.0, glTF 2.0 and USD. Each had the same 60 mistakes planted in it, plus 10 legal-but-odd decoys. Every format was judged only by its own official checkers. Then the Loom learned rules from half of the misses and was tested on the other half, which it had never seen.

One turn of the flywheel

Held-out half: own checkers → plus Loom rules

The rules were written only from learn-half misses, at most 5 per format, one general property each. They were committed before the held-out half was opened (sha256 9deab24a…). They raised no false alarms on the 10 decoys.

What the result says

X3D is the richest language here. It can state 53 of the 60 mistakes, against glTF's 48 and USD's 44. Only X3D can say "this event is wired wrong", "two materials on one surface", "this joint name is not a humanoid joint" or "this metadata number is not a number".

But its validator is not the best judge. The Khronos glTF-Validator checks values against each other and against the files. X3D's misses were counts, missing or non-image textures, a hierarchy cycle and bounds: exactly what a schema cannot see.

The Loom closes part of the gap, measurably. That is the flywheel: test, rule, better checker. The next turn is to put the five X3D rules into the validator itself.

Corrections found after the run (the score is left as registered)

  • F03 was not a fault in X3D. nearDistance = -1 means "automatic" in X3D, so it was legal. Excluding it, H1 against glTF still fails.
  • A01 in X3D was caught for the wrong reason. The finding was a schema position error, not the missing DEF.
  • glTF's NaN catches are JSON parse refusals. JSON cannot hold NaN, so the file never loads.
