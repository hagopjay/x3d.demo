# SLAB: read the snowpack, ski it or release it

A KANSEI avalanche game. The mountain, the skier and every saved snowpack are **X3D 4.0**; **PlayCanvas** draws them; the snow is a **material point method** (MLS-MPM with APIC) under the line you choose, with a slab on a buried weak layer that cracks, propagates and runs.

```
node tools/serve.mjs            # then open http://localhost:8080
```

| Key | Action |
|---|---|
| 1 / 2 | choose the line: Ridge (safe) or Bowl (deadly) |
| P | dig a pit: layers, density, hand hardness, a compression-test reading, the Föhn-style index |
| Y / N | predict "will it release?", scored against what happens |
| Enter | ski the line |
| C | patrol: charge the top of the roll |
| A | pull the airbag when caught |
| S | stress overlay: the weak layer coloured by shear / strength (it lights up before it goes) |
| V | camera: cross-section, chase, ridge |
| T | tinker panel, built from the level's `kansei:tunable` sets |
| R / L | reset / next level |
| F9 | save the live snowpack as X3D |
| drop a saved `.x3d` | resume it bit-exactly |

Bots for headless play: `?bot=naive`, `?bot=patrol`, `?bot=safe`, `?bot=airbag`.

## How it fits together

- **The solver** is `src/sim/mpm.js`, the float64 reference.
- **The GPU port** is `src/gpu/mpm-gl.js`: WebGL2, with points additively blended for particle-to-grid. It is checked against the reference live in the INTEGRITY panel (press **B** for the PIC wrong twin).
- **Levels** are `levels/level*.x3d`, generated by `tools/levels.mjs`. Each one holds:
    - the ElevationGrid the solver samples its terrain from;
    - `kansei:slab-level` (layers and lines);
    - `kansei:referee` (claims the tests re-prove);
    - `kansei:tunable` (the tinker panel).
- **Snapshots** (`src/x3d/snapshot.js`) hold `kansei:slab-state`, which carries every particle field as MetadataDouble and resumes bit-exactly, plus a PointSet that any X3D browser draws.
- **Physics, gates and what changed after the first runs:** `docs/PHYSICS.md`.

## Tests and gates

```
npm test                                             # fast gates live, slow ones from receipts
node tools/ladder.mjs                                # CPU gates -> receipts/gates.json
node tools/levels.mjs                                # level claims -> receipts/levels.json
NODE_PATH=$(npm root -g) node tools/gpu-gate.cjs     # GPU vs CPU -> receipts/gpu-cpu.json
NODE_PATH=$(npm root -g) node tools/playtest.cjs --bot=naive --shots=4
```
