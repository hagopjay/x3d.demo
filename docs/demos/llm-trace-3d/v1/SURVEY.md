# Survey: lineage and traceability tools in the X3D pipelines, and what carries over to an LLM trace

Read 2026-11-20 from shallow clones (commit shown) and `gh pr view`. Short by design: what each tool does, then what this folder took from it.

| tool | where (commit) | what it does |
|---|---|---|
| **x3dprov** | hagopjay/x3d.ML `src/x3dprov.py` (ef94650) | A hash chain kept in a scene's own `<head><meta name="x3dprov.step.N">`. Each step (generate, validate, repair, render, trace...) records `prev`, `input_sha256` and `output_sha256` (C14N hash of the scene with the prov metas removed). `verify()` relinks the chain and compares the last output hash with the file as it is now. A mismatch means the file was edited untracked. This is tamper *evidence* with no signing (0.1). |
| **x3dprov_trace** | x3d.ML `src/x3dprov_trace.py` | Records a value-level check as one non-mutating `op: "trace"` step: sources with their sha256, `claims_sha256`, `report_sha256`, a summary of verdict counts, and the items inline up to 64 KiB, otherwise in a sidecar file. The engine is injected, so the record can be audited by recomputing the check. |
| **x3dtrace** | x3d.ML `src/x3dtrace.py` (engine sha256 `dcba70d7...`, the same prefix chapter 23 and x3d.demo pin) | "A quote beside every value." A writer gives `{field, value, quote, source}`. Plain code with no model answers three questions: **FIND** (is the quote in the source, as a whole-token run, number-aware), **COMPARE** (is the value in the quote: numbers, vectors, colours, dates, units, text), **LOCATE** (character span, line and column, W3C Web Annotation selectors; for X3D also node path and world box). Verdicts are verified / check / reworded / unchecked, after the GAIK source_tracing vocabulary (MIT; independent implementation). Standard library only. |
| **x3dprov_provo** | x3d.ML `src/x3dprov_provo.py` | A lossless view of the chain in W3C PROV-O (Turtle / JSON-LD) with OWL-Time. Steps become `prov:Activity`, scene versions become `prov:Entity` (`wasDerivedFrom`, `wasRevisionOf`), and tools, models and validators become agents with roles. An untracked edit becomes a derivation with no activity, which SHACL flags. Round-trips to the same bytes. |
| **x3dprov_openlineage** | x3d.ML `src/x3dprov_openlineage.py` | A view of the chain as OpenLineage 2-0-2 RunEvents (one parent run per chain, one run per step, the scene as a dataset versioned by its content hash), so Marquez or any OpenLineage consumer can ingest an X3D loop. Times that were not recorded are marked `synthetic-order`. |
| **scene_evidence** | Web3DConsortium/x3d_mcp upstream `src/tools/scene_evidence.py` (8205047). *Not* in the local hagsmac fork (fa0b389). | The same claim check exposed as an MCP tool, plus BIND: the claimed value is tied to the scene's own attribute. The answer carries verdict words, offsets and handles rather than the quotes (`text="quoted"` adds a capped sample). Read-only, no model. |
| **scene_brief** | same repo, `src/x3d_utils/scene_brief.py` | A small, trust-tiered description of a scene sized to a byte budget (node counts, bounding box, text in counts or capped). It answers "where should I look" before an agent spends a large read. |
| **x3d_s1/evidence.py** | hagopjay/x3d.loom `x3d.s1/x3d_s1/evidence.py` (10d045e) | A small FIND/COMPARE/LOCATE for scene text, under the Loom laws. A verified quote caps a claim at grade L and never C (law 6). No quote means "unchecked", never "wrong" (law 13). A quote that the injection lint flags can never verify, and it is shown only escaped. |
| **claim ledger** | hagopjay/x3d.docs `docs/tools-shared/claims_lib.py`, chapter 23 `docs/learn/23-traceability-lineage.md` (f76331a) | The docs version: one JSONL line per number in a chapter (`{id, value, quote, source, grade}`), checked against pinned sources (git or raw fetch). Chapter 23 teaches the method and a seven-layer lineage stack, and says out loud what a check cannot show: that the quote is the *right* place, that the value is true, or who wrote the record. |
| **lineage report** | hagopjay/x3d-blender-io PR #45 (merged 2026-11-16), `source/lineage.py` | For each DEF'd attribute the X3D 4.0 exporter writes: which Blender datablock it came from, the conversion steps (axis, unit, sRGB, energy, FOV, Blinn-Phong fit), line, column and span, and a verdict from an independent recompute (tolerance 5e-7). `reverify` catches later edits. It shares no code with x3dtrace (GPL / MIT boundary). |
| **trace viewer demo** | hagopjay/x3d.demo PR #39 (merged), `docs/demos/x3d-trace-viewer/v1/` | Three panes: claims with verdicts, source text with the quote marked, and X_ITE with the box the claim points at. It has planted errors (labelled), "place 1 of 5" for repeated quotes, and live re-check in the browser (find and compare only). 8 of 8 engine boxes matched X_ITE 16.6.0's own bounding boxes. |

## What carries over to an LLM trace (Langfuse / LangSmith)

1. **The citation is a claim.** An LLM asked for structured output with `{field, value, quote, source}` citations hands you exactly x3dtrace's input. The retrieved documents and the tool outputs recorded in the trace are the sources. FIND, COMPARE and LOCATE then run with no model in the loop. **Used here**: `build.py` calls the vendored engine unchanged and colours each thread by its verdict. The planted "ships within 5 business days" (source: "7 to 10") comes back `check`.
2. **Verified is not "true" (chapter 23 and the x3d.demo limits).** The scene and the panel say "find / compare / locate", not "correct". The judge score (0.83) and the trace's own scores are shown as separate, attributed numbers (EVAL / API / ANNOTATION), not merged into the verdicts.
3. **"First hit" is wrong (x3d.demo "place 1 of 5", chapter 23).** This bit during the build: the value `5` first matched inside `2025-05-12`. The answer span now uses whole-token matches and picks among them by overlap with the quote's words, and the panel reports the number of candidates.
4. **Unknown is not zero (Loom law 13).** Observations without tokens or cost show no number rather than 0. The EVENT has no latency. The trace-level object is labelled as not schema-checked, because the current spec no longer documents it.
5. **Hash everything you read (x3dprov).** The scene's `<head>` carries the trace file's sha256, the Langfuse spec's sha256 and the x3dtrace engine's sha256. Not done yet: the x3dprov chain itself (`generate` step plus a `trace` step through `x3dprov_trace`). That is the natural next step and needs `lxml`.
6. **Views, not copies (provo / openlineage).** A Langfuse trace is already a PROV-shaped graph: observations are activities, inputs and outputs are entities, models and tools are agents. The same two views (PROV-O, OpenLineage RunEvents per observation, with `parentObservationId` → ParentRunFacet) would make an LLM run ingestible next to the X3D runs. Not built here.
7. **Untrusted text stays escaped (x3d_s1 law on injection).** Trace inputs and outputs are model and user text. The page writes them with `textContent` only, never `innerHTML`.
