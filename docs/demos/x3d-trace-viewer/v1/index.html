Lineage and provenance of values

Where a value came from, and where it sits

A claim is a value plus a short quote copied from the text it was read from. Plain code, with no model, checks three things: is the quote in the text (find), is the value inside the quote (compare), and where is it (locate). Pick a claim on the left: the middle shows the text with the quote marked, the right shows the box it points at in the 3D scene.

    What a verdict says

    • ✓ verified the quote is in the text as a whole run and the value is inside it.
    • ✕ check the quote is not there, or the value is not in it. A person looks.
    • ≈ reworded the value's words are in the quote but not the same numbers.
    • – unchecked no quote came with the value, so nothing could be checked. The coverage figure counts these.

    Verified is not proof the quote is the right place. Try "The back wall is the same 0.73 grey": verified, boxed at the floor. Step through the 5 places, then see the version that names the node.

    What runs where

    • The recorded verdicts, spans and boxes come from x3dtrace (Python, standard library), run when the page was built (build/build_trace.py).
    • The page re-checks live, in your browser, only find and a number or version compare: edit the text and the chips turn dashed. The full engine is not ported here.
    • Boxes are world-space boxes from the report. The check against X_ITE's own bounding boxes is in the notes below the page's checks.
    • The claims on this page were written by hand for it, including the planted errors. In a pipeline a model copies the quote; the checker does not care who wrote it.
