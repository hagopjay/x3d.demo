## Tinker without an API

1. **Artist:** change the foundry's cyan material in Blender, export X3D 4.0, and compare the material in X_ITE.
2. **Technical artist:** edit one city module's shared mesh and observe all placements; make copies single-user and repeat the size measurement.
3. **Animator:** modify a parent transform in the authored X3D or Blender source and compare occurrence-aware motion at the recorded sample times.
4. **BIM developer:** select a known IFC GlobalId and follow its metadata through X3D, GLB extras and USD scalar properties.
5. **Pipeline engineer:** add a new fixture or a deliberate failure, run the independent auditor, and verify that it reports the failed property rather than producing a green badge from file existence.

## A future assistant can be bounded by this contract

The scene recipes, source identity, versioned playlist, outputs and independent receipts are already structured data. A later LLM integration can edit parameters or propose a new chapter. Keep authoring separate from validation: no assistant should manufacture a receipt, change a warning into a pass, or declare an unexecuted Unreal/Bonsai handoff verified. The useful flywheel is new scenes → measured exchanges → retained examples and failures → better subsequent scene recipes.
