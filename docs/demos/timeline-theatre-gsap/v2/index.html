Theatre.js · GSAP · X3D

Write the timeline once.
Play it everywhere.

Below, one GSAP timeline (about 20 lines of JavaScript, 24 satellites, a core, a camera move) has been compiled into plain X3D: a TimeSensor, interpolators and ROUTEs. The file contains no script. X_ITE and a three.js renderer each read the same file and move together (set the clock to autonomous and each runs it alone; the conductor only sends them the playhead so you can scrub). Then you get the compiler's dials and the real GSAP curves to check it against.

The compiler, with the dials in your hand

X3D interpolators are straight lines between keys. Eases are curves. Move a slider: the page re-bakes the timeline in your browser, writes new X3D, and reloads both engines. The file shrinks; the error against GSAP itself grows. You choose the trade.

The exporter reads a Theatre.js state file (JSON the author's studio saved) and evaluates it with @theatre/core. The studio package is never imported, bundled or served here, and the X3D that comes out contains no Theatre code. If you embed the studio in a page you ship to users, its AGPL terms apply to that page. This page has no Theatre code at all: the Theatre curves are samples that core evaluated earlier (data/theatre-box.oracle.json).

GSAP loads from jsDelivr and runs in your browser for the orrery. Its licence is free for most uses, not for every one (for example, a tool that lets people build visual animation tools without GSAP's own Business licence); read gsap.com/standard-license before using it in a product. The exported X3D contains none of it. Engineering notes, not legal advice.
